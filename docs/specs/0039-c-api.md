# 0039 — C API: libyubiblob, a Blob Store on the YubiKey

**Status:** implemented
**App:** yb
**Implemented in:** 2026-10-14

## Problem

yb is usable from programs only through the `yb` command.  The KeePassXC
mock-up (spec 0030, branch `yb-device-storage`) runs it as a subprocess,
and pays for it:

- **The PIN crosses a pipe** to another process (spec 0037).
- **Errors are text:** several YubiKeys are recognized by the words
  "ambiguous device selection", a wrong PIN by "PIN".
- **Metadata is coarse:** a changed blob is detected from `yb ls -l`,
  whose time is to the minute.
- **Each call starts a process** (about 0.3 s), several times per open.

A library in the program's process removes all four.  It must serve any
application that wants a small, safe store on a YubiKey (a password
manager is the first), not KeePassXC alone, and must not rule out
Windows, where KeePassXC also ships.

## Goals

- **G1 — A generic blob store.**  List, fetch, store and remove named
  blobs on a YubiKey set up for yb, with yb's guarantees: interruptions
  lose nothing, reads never write, tampering is detected
  (`docs/invariants/`).  Nothing application-specific: no vaults, no
  password files, no caching policy.
- **G2 — A C interface.**  Callable from C and C++ (and anything with a
  C FFI), with no Rust types crossing it, a header generated from the
  code, and explicit rules for memory, strings, errors and threads.
- **G3 — Typed errors.**  Every function returns a status code that a
  caller can act on (not found, store full, wrong PIN with tries left…),
  with a message for people.
- **G4 — Exact change detection.**  Each blob has a generation, which
  changes with every write of it, readable without the PIN.
- **G5 — Secrets handled as in yb.**  The PIN is passed as bytes,
  copied into zeroizing memory, and dropped after the call; fetched
  content is returned in a buffer that is zeroized when freed.
- **G6 — Windows-clean from the start.**  The library builds and its
  tests pass on Windows in CI (against the simulated YubiKey); no
  Unix-only assumption in the interface or the code.
- **G7 — A versioned interface.**  An ABI version, checked at run time;
  until 1.0, changes are allowed between minor versions and announced;
  from 1.0, only additions within a major version.

## Non-goals

- **Application semantics:** vault naming, stored master passwords,
  caching, save delays (KeePassXC's, spec 0030).
- **Setting up a YubiKey:** `yb format`, PIN and PUK changes, management
  key rotation, `fsck`: the command's job.  The library assumes a
  YubiKey set up with `yb format`, its management key kept on the
  YubiKey and unlocked by the PIN (decided 2026-10-14), and reports one
  that is not (`YUBIBLOB_ERR_NO_STORE`).  Setting up from an application (for
  KeePassXC users who would rather not use a command line): later, if
  KeePassXC's team asks.
- **An explicit management key** (one not kept on the YubiKey):
  impractical with yb in general; not supported.
- **Interactive behavior:** device picker, prompts, LED flashing.
- **Packaging beyond Linux** (a vcpkg port for Windows and macOS
  builds), and KeePassXC on Windows: later, on request.
- **A subprocess backend in KeePassXC:** the mock-up keeps it on its
  branch; it is not maintained beside the library (decided 2026-10-14).
- **A simulated YubiKey for applications' tests, in 0.1** (decided
  2026-10-14).  Applications should be able to test against libyubiblob's
  real code rather than a mock of it (a mock drifts: the KeePassXC
  mock-up's stand-in for `yb ls` failed where the real one succeeded).
  The simulators exist, and yb's own regression tests run on them: the
  lightweight one, `VirtualPiv` in `yb-core` (the PIV operations in
  memory, persisted to a file, with fault injection: interrupted writes,
  a card out of memory), behind every tier-1 test; and the heavyweight
  one, a full PIV application emulated by `piv-authenticator` behind a
  virtual smart-card reader (`vsmartcard`), run in the NixOS VM test
  (tier 2).  Exposing the lightweight one through the C interface (e.g.
  `yubiblob_open_simulated(path, …)`, an explicit call, not an
  environment variable) is a later addition.
- **Asynchronous calls or progress callbacks:** calls block; a caller
  runs slow ones (a 22 KB store takes 4 s) on its own thread.

## Specification

### Packaging

- A new crate in the yb workspace, `rust/yubiblob` (crate `yubiblob`),
  over `yb-core`.  The library's names derive from `yubiblob`, not from
  the command's short `yb`, so as not to clash in shared namespaces
  (installed files, pkg-config, C symbols, distribution packages)
  (decided 2026-10-14): `libyubiblob` (`libyubiblob.so.0.1` before
  1.0, where each minor version may break callers, then
  `libyubiblob.so.1`; `libyubiblob.a`, `yubiblob.dll`, `yubiblob.lib`),
  header `yubiblob.h`, pkg-config `yubiblob`.
- Built and installed with `cargo-c` (decided 2026-10-14): it runs
  `cbindgen` for the header, builds the versioned shared and the static
  libraries, writes the pkg-config file, and installs them, on Linux and
  on Windows (`.dll`, `.lib`, `.def`).
- Version: its own, starting at 0.1.0, independent of the `yb` command;
  `YUBIBLOB_ABI_VERSION` in the header, `yubiblob_abi_version()` in the
  library.
- License: MIT, as the rest of yb (fits KeePassXC's GPL).

### Conventions

- Prefix `yubiblob_`; types `yubiblob_*_t`; constants `YUBIBLOB_…`; all
  functions are `extern "C"`.
- Strings: UTF-8, NUL-terminated; blob names as yb accepts them (1 to
  255 bytes, no NUL).
- Every function returns `yubiblob_status_t`; results come through out
  parameters, written only on success.
- Memory the library returns is freed with the matching `yubiblob_*_free`
  function, never with `free()`; freeing NULL is a no-op.
- A thread-local message describes the last failure on the calling
  thread: `const char* yubiblob_last_error(void)`, valid until that thread's
  next call into the library.  English, for people, not for parsing.
- A panic inside the library never crosses the interface: it becomes
  `YUBIBLOB_ERR_INTERNAL`.

### Status codes

| Code | Meaning |
|---|---|
| `YUBIBLOB_OK` | success |
| `YUBIBLOB_ERR_NOT_FOUND` | no blob of that name |
| `YUBIBLOB_ERR_STORE_FULL` | not enough free objects (checked before writing; the card's memory can still run out while writing, see `YUBIBLOB_ERR_CARD_FULL`) |
| `YUBIBLOB_ERR_CARD_FULL` | the card ran out of memory while writing; blobs keep their previous content (invariant 0001) |
| `YUBIBLOB_ERR_WRONG_PIN` | wrong PIN; `yubiblob_last_pin_tries()` gives the tries left |
| `YUBIBLOB_ERR_PIN_BLOCKED` | PIN blocked |
| `YUBIBLOB_ERR_NO_DEVICE` | no YubiKey connected (or none with that serial) |
| `YUBIBLOB_ERR_SEVERAL_DEVICES` | several connected and no serial given |
| `YUBIBLOB_ERR_NO_STORE` | the YubiKey is not set up for yb |
| `YUBIBLOB_ERR_CARD_REMOVED` | the YubiKey was removed during the call |
| `YUBIBLOB_ERR_CORRUPTED` | the blob's signature does not verify (invariant 0006) |
| `YUBIBLOB_ERR_DEFAULT_CREDENTIALS` | refused: factory PIN or PUK (spec 0024), unless allowed at open |
| `YUBIBLOB_ERR_INVALID_ARGUMENT` | bad name, NULL pointer, bad flags |
| `YUBIBLOB_ERR_INTERNAL` | anything else; see `yubiblob_last_error()` |

### Functions

```c
uint32_t yubiblob_abi_version(void);
const char* yubiblob_version(void);              /* "0.1.0" */
const char* yubiblob_last_error(void);
int yubiblob_last_pin_tries(void);               /* after YUBIBLOB_ERR_WRONG_PIN */

/* Devices: no PIN. */
typedef struct {
    uint32_t serial;
    char* firmware;                        /* "5.7.1" */
    bool has_store;
} yubiblob_device_t;
yubiblob_status_t yubiblob_list_devices(yubiblob_device_t** devices, size_t* count);
void yubiblob_devices_free(yubiblob_device_t* devices, size_t count);

/* A session on one YubiKey; serial 0: the only one connected. */
typedef struct yubiblob_session yubiblob_session_t;
#define YUBIBLOB_OPEN_ALLOW_DEFAULT_CREDENTIALS 0x1
yubiblob_status_t yubiblob_open(uint32_t serial, uint32_t flags, yubiblob_session_t** session);
void yubiblob_close(yubiblob_session_t* session);

/* Blobs: no PIN. */
typedef struct {
    char* name;
    uint32_t size;                         /* plaintext size */
    uint32_t stored_size;
    uint32_t mtime;                        /* Unix seconds */
    uint32_t generation;                   /* changes with every write */
    bool encrypted;
    yubiblob_signature_t signature;              /* VERIFIED, UNSIGNED, UNVERIFIABLE, CORRUPTED */
} yubiblob_blob_info_t;
yubiblob_status_t yubiblob_list(yubiblob_session_t* s, yubiblob_blob_info_t** blobs, size_t* count);
void yubiblob_blobs_free(yubiblob_blob_info_t* blobs, size_t count);
yubiblob_status_t yubiblob_stat(yubiblob_session_t* s, const char* name, yubiblob_blob_info_t* info);
void yubiblob_blob_info_clear(yubiblob_blob_info_t* info);

/* Store room: no PIN. */
typedef struct {
    uint32_t object_count;
    uint32_t free_objects;
} yubiblob_store_info_t;
yubiblob_status_t yubiblob_store_info(yubiblob_session_t* s, yubiblob_store_info_t* info);

/* Content: the PIN as bytes (not NUL-terminated). */
yubiblob_status_t yubiblob_fetch(yubiblob_session_t* s, const char* name,
                     const uint8_t* pin, size_t pin_len,
                     uint8_t** data, size_t* len);
void yubiblob_buffer_free(uint8_t* data, size_t len);  /* zeroizes */

#define YUBIBLOB_STORE_ENCRYPT  0x1
#define YUBIBLOB_STORE_COMPRESS 0x2
yubiblob_status_t yubiblob_store(yubiblob_session_t* s, const char* name,
                     const uint8_t* data, size_t len, uint32_t flags,
                     const uint8_t* pin, size_t pin_len);
yubiblob_status_t yubiblob_remove(yubiblob_session_t* s, const char* name,
                      const uint8_t* pin, size_t pin_len);
```

- `yubiblob_fetch` checks the blob's signature before decrypting (spec 0033):
  `YUBIBLOB_ERR_CORRUPTED` returns nothing.  An unsigned blob is returned.
- `yubiblob_store` is the rip-safe replace (spec 0031), with the clean-up
  first (spec 0038); the management key is the one kept on the YubiKey,
  unlocked by the PIN (spec 0027).
- `yubiblob_list` and `yubiblob_stat` never write (invariant 0002).

### Threads

A session is used by one thread at a time; separate sessions may be
used from separate threads.  The library holds no global state besides
the thread-local error message.

### Tests

- `rust/yubiblob/tests/api.rs`: the `extern "C"` functions on simulated
  YubiKeys (`YB_FIXTURE`), each set up as `yb format` would: version;
  devices; store, list, stat, store info, fetch and remove, with the
  generation changing at each store; unencrypted blobs; not found; wrong
  PIN (with tries left; nothing written); store full (nothing written);
  a tampered blob (`CORRUPTED`, content not returned); factory
  credentials (refused unless allowed); no store; invalid arguments, and
  freeing NULL.  Removing the signature check, or the "store full"
  status, fails them.
- `rust/yubiblob/src/lib.rs` (unit): the card's answers as status codes
  (wrong PIN with tries, PIN blocked, card full under context, card
  removed, no reader, several YubiKeys); a panic becomes
  `YUBIBLOB_ERR_INTERNAL`.
- `scripts/check-libyubiblob`: the library installed with `cargo-c` into
  a temporary prefix, `rust/yubiblob/tests/c/smoke.c` compiled through
  its pkg-config file (`-Wall -Wextra -Werror`), run on a YubiKey
  simulated in a file and set up by the real `yb format`.
- CI: the above on Linux; on Windows (`windows-latest`), the Rust tests
  and a `cargo cbuild`.
- Not tested: that freed buffers are overwritten (reading freed memory
  is undefined behavior); on a real YubiKey, by hand (the C program
  takes the PIN as its argument).

## Invariants

- Exposed, not new: 0001, 0002, 0003, 0005, 0006, 0007 (sessions are
  bound to one YubiKey), 0011 (messages name no serial, reader or
  secret), 0013 (the management key, and now the PIN, in zeroizing
  memory).
